# ProTest — Архитектура и техническое описание системы

## 1. Обзор архитектуры
Система **ProTest** построена на основе модульного монолита с разделением на:
- **Backend (API):** NestJS (TypeScript), Prisma ORM, PostgreSQL (или SQLite для автономной разработки), Redis, JWT.
- **Web Client:** React + Vite + TypeScript, Tailwind CSS (фиолетовая тема), KaTeX (рендеринг математических формул).
- **Android Client:** Kotlin, Jetpack Compose, Retrofit, Room (офлайн-кэширование ответов при обрыве связи), WorkManager.
- **Инфраструктура:** Docker, Docker Compose, Nginx Reverse Proxy.

---

## 2. База данных и структура сущностей
- **User:** Пользователи с ролями `ADMIN`, `TEACHER`, `STUDENT`.
- **OtpVerification:** 6-значный код (+998), 5 минут TTL, ограничение до 5 попыток, 60 секунд задержка между отправками.
- **Topic:** Иерархический каталог из 185+ математических тем с неограниченной вложенностью (`parentId`), архивацией и сортировкой.
- **Question:** Математический вопрос с уникальным ID, условием (текст + KaTeX-формула + изображение JPEG/PNG), сложностью (`EASY`, `MEDIUM`, `HARD`, `OLYMPIAD`), баллами и пояснением.
- **Option:** Варианты ответа (A, B, C, D и др.) с текстом, KaTeX формулой и флагом `isCorrect`.
- **Test:** Конструктор тестов со спецификацией длительности, параметров перемешивания (`shuffleQuestions`, `shuffleOptions`), повторных попыток и назначения группам.
- **TestAttempt:** Попытка тестирования с серверным таймером (`startedAt`, `expiresAt`) и **замороженным снимком** (`shuffledSnapshot`).
- **StudentAnswer:** Ответы студента, проверяемые строго по `Option ID` (а не буквам).
- **AuditLog:** Системный журнал действий для администратора.

---

## 3. Критический алгоритм перемешивания и защиты (Раздел 6 ТЗ)
1. При старте попытки сервер генерирует индивидуальный порядок вопросов (если включен `shuffleQuestions`) и вариантов ответа (если включен `shuffleOptions`).
2. Сервер формирует JSON-снимок `shuffledSnapshot`, в котором:
   - Каждому варианту присваивается новая буква (A, B, C, D) для отображения.
   - **Поле `isCorrect` полностью удаляется**, исключая утечку правильных ответов через код страницы / DevTools!
3. Снимок сохраняется в таблице `TestAttempt`. При перезагрузке страницы или смене устройства ученик видит ровно тот же порядок вариантов.
4. Проверка правильности производится исключительно на сервере по совпадению `Option.id`.

---

## 4. Контроль таймера на сервере (Раздел 8 ТЗ)
- Время окончания `expiresAt` рассчитывается и фиксируется на сервере при создании попытки.
- Клиентский таймер лишь визуализирует оставшееся время.
- Сервер отклоняет сохранение ответов, если `now > expiresAt`, и автоматически переводит попытку в статус `COMPLETED`.
